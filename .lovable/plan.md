## محتوى الملف المقترح

1. **مصدر البيانات**: Supabase مستقل (مشروع جديد، بدون استيراد) هو مصدر الحقيقة الوحيد. Lovable Cloud مستبعد نهائيًا ولا يوجد تبديل تلقائي مستقبلي. مبررات + آثار على العميل/الخادم.
2. **حدود الوحدات (Modules)** — أسماء مقترحة ومبررات، دون إنشاء جداول:
   - الهوية والكيانات (identity)
   - العقارات والمشاريع (properties / projects)
   - القوالب والمراحل (templates / phases)
   - العقود والمراسلات (contracts / correspondence)
   - المستندات والتقارير (documents / reports)
   - الخدمات والمالية (services / finance)
   - الإشعارات والتدقيق (notifications / audit)
3. **Naming conventions**: snake_case للجداول والأعمدة، جمع لأسماء الجداول، مفاتيح نطاق حسب السياق (`entity_id`, `project_id`, `created_by`, `owner_id`) بدون فرض مفتاح نطاق واحد موحّد، أعمدة زمنية قياسية `created_at/updated_at/deleted_at`.
4. **الهوية**: `auth.users` هو المصدر الوحيد لتسجيل الدخول. نموذج: مستخدم واحد ← حساب شخصي ← عضويات متعددة في كيانات، كل عضوية بدور خاص بها. الأدوار في جدول عضويات/أدوار منفصل — ممنوع تخزين الدور في الملف الشخصي.
5. **حدود العزل**: Tenant/Entity/Project — قواعد العزل الإلزامية، أن كل استعلام يمر عبر مفتاح النطاق، وأن RLS ستُبنى على دوال `SECURITY DEFINER` لاحقًا.
6. **السياسات العامة**: Soft delete (`deleted_at`)، Versioning للمستندات/العقود، وسجل تدقيق موحّد (من فعل ماذا ومتى وعلى أي كيان) للوحدات الحساسة.
7. **قرارات مؤجلة**: المخطط التفصيلي وRLS، ربط GitHub بـ`1127410650/11`، التفعيل الفعلي لـSupabase.
