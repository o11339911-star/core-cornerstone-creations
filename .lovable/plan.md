## ثانيًا: المرحلة 28 — الاختبار الشامل التجريبي

### قواعد عامة تسري على كل الدفعات

- **حسابات TEST فقط بالبادئة `p28-*`** وكيانات/مشاريع بالبادئة `TEST-28`. **ممنوع لمس** حسابات العرض الدائمة الـ15 و`admin@rakeez.app` وكياناتها الخمسة (تُستخدم للقراءة فقط عند الحاجة لمقارنة عزل).
- **بلا إصلاحات أثناء التنفيذ**: كل خلل يُسجَّل في سجل عيوب واحد `.lovable/tests/28-defects.md` بدرجة (Critical / High / Medium / Low) ويُرحَّل لدفعة إصلاح مستقلة بعد إغلاق الاختبار — إلا في حالة نقطة التوقف أدناه.
- **نقاط التوقف الإلزامية**: عند أي (أ) تسرب بيانات بين حسابات/كيانات/مشاريع، أو (ب) عطل وظيفي Critical يمنع مسارًا أساسيًا، أو (ج) كتابة تتم بلا صلاحية — **أتوقف فورًا**، أوثّق الدليل، وأنتظر قرارك قبل متابعة بقية الدفعات.
- **الأدلة لكل سيناريو**: نتيجة Pass/Fail، لقطة شاشة للحالة النهائية (عبر متصفح مؤتمت على المعاينة المحلية)، وناتج استعلام تحقق من القاعدة عند وجود أثر بيانات، وحصيلة console/network لكل صفحة تُزار.
- **التنظيف**: كل دفعة تنتهي بحذف بياناتها بترتيب عكسي للاعتماديات، ثم استعلام تأكيد صفر بقايا بالبادئة `p28`/`TEST-28`. تنظيف نهائي شامل في الدفعة 28-J.
- **الاختبارات الارتدادية (Regression)**: بعد كل دفعة أُعيد تشغيل «حزمة الدخان» القصيرة: دخول → اختيار حساب نشط → لوحة المشروع → فتح تقرير → فتح المالية → تسجيل خروج. أي كسر فيها = نقطة توقف.
- **صفر تعديل** على Auth أو القاعدة أو RLS أو Storage أو الإعدادات أو الكود التنفيذي، عدا إنشاء/حذف صفوف بيانات TEST.

### الدفعات

**28-A — الأساس: الهوية والحساب النشط والتنقل**
- حسابات: `p28-owner-a`, `p28-member-a`, `p28-owner-b`, `p28-noaccount`.
- إيجابي: دخول، اختيار حساب نشط، تبديل بين حسابين، بقاء الحساب النشط بعد Refresh وDeep link، تسجيل خروج.
- سلبي: كلمة مرور خاطئة، دخول بحساب بلا عضوية (يجب مسار واضح لا شاشة بيضاء)، زيارة مسار محمي بلا جلسة (تحويل إلى `/auth`)، رجوع بالمتصفح بعد الخروج لا يكشف بيانات.
- أدلة: لقطات المسارات الأربعة + سجل console نظيف.

**28-B — الكيانات والعضويات والدعوات والفرق**
- حسابات: `p28-owner-a`, `p28-admin-a`, `p28-member-a`, بريد دعوة `p28-invitee`.
- إيجابي: إنشاء كيان TEST، دعوة عضو بدور، قبول الدعوة، تغيير دور، إيقاف عضوية.
- سلبي: قبول دعوة بحساب مختلف عن المدعو، إعادة استخدام رابط دعوة مستهلك، دعوة مكررة، عضو عادي يحاول تغيير الأدوار (رفض خادمي لا واجهي فقط)، وصول `p28-owner-b` لكيان A.
- أدلة: ناتج `private.can` الفعلي للأدوار الثلاثة على وحدة الفرق.

**28-C — العقارات والمشاريع والأطراف**
- إنشاء عقار TEST، مشروع TEST، إضافة أطراف (مالك، مقاول، استشاري، مسوّق).
- سلبي: طرف مشروع يحاول رؤية مشروع آخر داخل نفس الكيان؛ طرف خارجي يحاول تعديل بيانات المشروع؛ حجب الموقع الدقيق لمن لا يملك الصلاحية.
- أدلة: مصفوفة (دور × وحدة × فعل) بنتائج مقروءة من القاعدة.

**28-D — العقود والمراحل والتنفيذ والزيارات**
- إيجابي: عقد بإصدارين، مراحل هرمية ونسب إنجاز، زيارة موقع بمرفق.
- سلبي: تعديل إصدار عقد مُعتمد، تجاوز 100% إنجاز، زيارة بتاريخ خارج نطاق المشروع، تحديث متزامن لنفس المرحلة من جلستين (اختبار تزامن).

**28-E — الطلبات والمحادثة والمرفقات والمستندات**
- إيجابي: طلب جديد → رد → إغلاق؛ رسالة بمرفق؛ رفع مستند بإصدارين وتحليله.
- سلبي: رؤية رسائل بمستوى ظهور أعلى من دور المستخدم، تنزيل مرفق برابط مباشر من حساب آخر، رفع نوع ملف غير مسموح، إرسال مكرر سريع (idempotency/تكرار).

**28-F — التقارير والاعتمادات والخدمات والعدادات**
- إيجابي: إنشاء تقرير من قالب، تصدير، مسار اعتماد متعدد، عدادات الخدمات.
- سلبي: اعتماد ذاتي لمن أنشأ (فصل الواجبات)، تعديل تقرير معتمد، تجاوز حدود الباقة/العداد.

**28-G — المالية والدفعات والإغلاق والضمان والأرشفة**
- إيجابي: قيد مالي مزدوج متوازن، دفعة، إغلاق مشروع بقائمة تحقق، ضمان، أرشفة.
- سلبي: دور بلا صلاحية مالية يحاول القراءة والكتابة (يجب رفض خادمي)، إغلاق بقائمة تحقق ناقصة، قيد غير متوازن، تعديل بعد الأرشفة.

**28-H — إدارة ركيز الداخلية والوحدات العامة**
- حساب موظف منصة TEST مؤقت `p28-staff` (يُحذف في التنظيف).
- إيجابي: طابور المراجعة، التوزيع، Break-glass بسبب مسجّل، لوحة التكاملات (mock).
- سلبي: مستخدم عادي يفتح `/platform/*`، Break-glass بلا سبب، تعديل تكامل إلى live.
- الوحدات العامة وفق Feature Flags الحالية: الملف العام `/e/$slug`، تحقق التسويق `/mp/$token`، تحقق التقرير `/verify/$token`، وسائط 360، السوق والمواعيد والتجارة — لكل منها: مسار anon حقيقي + تأكيد صفر تسرب حقول حساسة + سلوك رمز ملغى/منتهٍ.

**28-I — اللغة والاتجاه والأجهزة وحالات الواجهة**
- كل صفحة رئيسية بالعربية RTL والإنجليزية LTR: صفر نص إنجليزي مسرّب في العربية، صفر overflow أفقي، أهداف لمس ≥44px.
- مقاسان: 390×844 (جوال) و1280×800 (كمبيوتر).
- الحالات الأربع لكل صفحة: Loading (skeleton)، Empty (SoftEmpty)، Error (رسالة عربية + إعادة محاولة)، Unauthorized.
- أدلة: لقطتان لكل صفحة (جوال/كمبيوتر) في كل لغة للصفحات الحرجة.

**28-J — الجودة التقنية والتنظيف النهائي**
- Typecheck + Build كاملين، مراجعة سجل console وnetwork لكل المسارات المزارة (صفر أخطاء غير مبرَّرة، وكل 4xx متوقع يُعلَّل).
- Deep links لكل مسار محمي بعد Refresh، وسلوك زر الرجوع.
- حذف كل بيانات `p28`/`TEST-28` + استعلام تأكيد صفر بقايا، وتأكيد سلامة حسابات العرض الدائمة الـ15 والكيانات الخمسة.
- تقرير نهائي: جدول Pass/Fail لكل سيناريو + سجل العيوب مرتّبًا بالخطورة + قائمة مخاطر الإطلاق المؤجلة من 27.
